## How I approach security and AI

- **Layer defenses.** Input checks, tool boundaries, output inspection, and human approval address different risks. No single filter establishes that an AI system is safe.
- **Make claims testable.** Publish limitations alongside results. The [prompt-injection benchmark](https://github.com/shanemhamilton/llm-prompt-guard/blob/main/benchmarks/PUBLIC_RESULTS.md) includes missed attacks, not just successful detections.
- **Bound automation's authority.** Use explicit scope, approval requirements, and recoverable changes rather than assuming an agent should act on every available capability.
- **Preserve accountability.** Keep evidence of what ran, what changed, what was reviewed, and what remains unknown.

These repositories show my engineering approach to AI security and governance. Each project's documentation distinguishes implemented mechanisms from evaluation results and operational claims.
